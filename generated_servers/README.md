# `generated_servers/`

This is the **output directory** for the build flow — nothing here is meant
to be hand-written. Every `.py` file is generated by
[`backend/generator.py`](../backend/generator.py) from the single template at
[`mcp_server/template.py`](../mcp_server/template.py), one file per
deployed database (`{database_name}_server.py`).

Each generated server:
- Exposes one MCP tool, `run_query`, that accepts a SQL `SELECT` and refuses
  every write/DDL statement (guard logic embedded from
  [`mcp_server/sql_validator.py`](../mcp_server/sql_validator.py), alongside
  [`mcp_server/errors.py`](../mcp_server/errors.py) and
  [`mcp_server/audit.py`](../mcp_server/audit.py)).
- Reads its database connection string from the `MCP_DB_URL` environment
  variable at launch — **no credentials are ever written to these files.**
- Runs as its own process over HTTP (`backend/deploy.py` launches it and
  assigns the port); `backend/routes/build.py` and `backend/routes/ask.py`
  then talk to it as an MCP client (via `backend/mcp_client.py`).

`registry.json` in this same directory is the host-application registration
list (Claude-Desktop-style `mcpServers` entries) — written by
`POST /api/register/{id}` and read back on API startup to restore active
deployments.

## Why most of this folder is git-ignored

See `.gitignore`: `generated_servers/*.py` and `generated_servers/registry.json`
are excluded because a generated server file has the shape of a credential
carrier and a real deployment's `registry.json` can leak internal
URLs/database names. Only this README and `.gitkeep` are tracked. Locally
you'll typically see this folder populated with real generated servers from
whatever databases you've connected — that's expected; they regenerate
automatically the next time you deploy, and can be deleted freely.
